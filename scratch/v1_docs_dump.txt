## 1. Project Philosophy

This is **not** a universal trading system. Three specific strategies were
devised through a dedicated research process and shortlisted from a larger
candidate pool:

1. **Ghost Grid** — Mean-reversion accumulation (ranging/stable regimes)
2. **SuperTrend** — Trend-following via K-Means optimal factor (trending regimes)
3. **CAB Watcher** — H4 inversion detection (exhaustion/reversal regimes)

Each strategy could run independently, but they run together as a unified
process for a specific reason: **markets operate in regimes** (ranging,
trending, exhaustion). One model thrives in ranging conditions while another
thrives in trending conditions. By running them together and sharing market
knowledge through the Knowledge Register, each bot can potentially help the
others achieve collective profitability across all market states.

**Current Phase: Raw Edge Validation**
Before introducing any filters, restrictions, or optimizations, the system
must first validate whether a raw mathematical edge exists. Every signal
generated by the bots must flow unobstructed to the market so that the
resulting data can be analyzed to determine:
- Which pairs each bot performs best on
- Which regimes produce winners vs losers
- Whether the shared-knowledge hypothesis holds
- What statistically-informed filters (if any) should be introduced

**[PERMANENT MANDATE] Knowledge Register Purpose:**
The Knowledge Register exists strictly to gather and serialize raw market
state information alongside trade outcomes. It must NEVER be used to
arbitrarily block, filter, or restrict trades. Any future filters must be
statistically derived from the raw data analysis — mapping why trades win
vs. lose in specific market behaviors/regimes — not from human intuition
or preference.

**Core principle (finalised May 2026):**
Every exit decision must be driven by market intelligence, not rigid
R-thresholds. R-multiples measure what happened. Market state tells you
what is happening.

**Exit intelligence roadmap (Market Exit Score, Phase 3):**
After raw edge validation, static R-threshold exits will be replaced
or supplemented by a continuous Market Exit Score (MES, 0-1) computed from:
regime alignment (30%), conviction trend (25%), ATR trajectory (20%),
directional momentum (15%), opposite signal quality (10%). MES < 0.30
exits regardless of R level.

**The finish line — Gate 6:**
One unified process, micro-lot sizing, avg R > 0.3 over 50 live trades on
validated bot-instrument pairs.

## 5. Thread Architecture

```
Main thread (60s)       equity heartbeat, circuit breaker, magic isolation, MT5 health
Thread 1 GhostWatcher   market pulse ADX/ATR/conviction → SharedState (2s pulse)
Thread 2 GhostHunter    M1 probe detection → fires 201/202/204 (1s loop)
Thread 3 CABWatcher     manages open CAB positions fluid matrix (15s cycle)
Thread 4 CABEntry       H4 inversion detection → fires 999555 (30s cycle)
Thread 5 SuperTrend     M30 trend following → fires 11 pairs (101234–408213) (30s cycle)
```

All threads share one MT5Gateway instance. The gateway threading.Lock
serialises every MT5 API call. One connection, one lock, no race conditions.

## 6. Bot Details — Ghost Grid

**Strategy:** Virtual ghost grid accumulates in memory against a probe move.
Fires real entry at exhaustion point. Mean-reversion philosophy — active in
RANGING/STABLE only. Primary instrument: XAUUSDm.

### Entry legs

| Magic | Leg | Gate | TP | SL |
|---|---|---|---|---|
| 201 | SCALP | Always | 1.0R | 0.35xATR |
| 202 | REVERSAL | ADX <= 40 AND conviction <= 60 | 1.5R | 0.35xATR |
| 203 | TREND-FOLLOW | **REMOVED** (Shifted to SuperTrend) | -- | -- |
| 204 | GHOST CACHE | nth virtual layer reached | 2.0R | nth_layer +/- 0.5xATR |

SL note: Was 0.2xATR — confirmed from 2-week data as the single largest
loss driver (41.5% of 201/202 trades hit SL before reaching BE-lock,

unified_runner.py and ghost_sniper.py now read SCALP_REV_SL_ATR_MULT = 0.35.

### Grid management thresholds

| Threshold | Value | Action |
|---|---|---|
| Grid TP | combined R >= +1.0R | Close all remaining legs, reset GridState |
| Grid Stop | combined R <= -3.0R | Close all immediately |
| Grid Protector | combined R >= +0.35R | Oldest leg SL to BE + 30pts, once per grid |
| BE-lock ratchet | individual R >= +0.5R | SL to breakeven + 30pts (one-time per leg) |
| Max grid age | 72 hours | Force-close and reset stale timeout safety valve |
| MAX_LEGS | 4 | Hard cap — never raise during demo testing |

### Ghost Cache (magic 204)

```

CACHE_INVALIDATION_N   = 2      reaches nth+2 layer = trend, invalidate cache
```

## 7. Bot Details — SuperTrend v2.3

**Strategy:** M30 trend following with K-Means optimal factor selection.
K-Means runs over last 100 bars of vol-adjusted performance across all
factor variants, clusters into Best/Average/Worst — this is the genuine
innovation over fixed-parameter SuperTrend systems.

SuperTrend was effectively dormant in Week 1 (2 trades, both winners, but
n=2 is meaningless). Root cause not yet confirmed — session gate + conviction
gate + K-Means factor selection may be stacking into a too-narrow window.
This needs investigation before Gate 3 data can be collected.

### State machine
```
INCUBATING  waits incubation_bars_trending=2 M30 bars before active management
CONFIRMED   SI high, R-lock ratchet active, ST-line trailing
DECAYING    SI dropping, tighten trail, close after decaying_tolerance_bars
DEAD        close immediately (ST flip, SI collapse, ER churn)
```

### R-lock ratchet (CONFIRMED state)
```
+1R  SL to entry + 30pt buffer (BE lock)
+2R  SL to entry + 1x risk (lock 1R)
+3R  SL to entry + 2x risk (lock 2R)
```

## 8. Bot Details — CAB Watcher

**Strategy:** H4 two-bar inversion entry + fluid position management across
ALL symbols. Multi-symbol was a critical bug in Week 1 — only XAUUSDm
positions were ever managed. Fixed Jul 2026.

### Entry pattern (cab_entry.py)
```
Bullish: bar[-3] bearish AND bar[-2] bullish = BUY
Bearish: bar[-3] bullish AND bar[-2] bearish = SELL
```
- Bar-aware cache: fires once per H4 bar close
- Retry bound: max 3 order attempts per detected bar signal
  (was unlimited — retried every 30s for up to 4 hours on persistent failure)
- max_positions = 4 per symbol
- Lot sizing: ATR-based, capped at max_lot_demo_cap = 0.01
  (FX fills were 0.14-0.32 lot in Week 1 due to missing cap)
- Session gate: blocks 00:00-07:00 UTC
- Spread guard: blocks if spread > 50 points

### Management matrix (cab_watcher.py)

| Milestone | Condition | Action |
|---|---|---|
| PROTECTOR | R >= 1.2R | SL to BE + M15 ATR buffer, once per ticket |
| CONT_TIGHTEN | R > 0, post-protector | Light tighten 0.10xM15 ATR per cycle |
| HARVESTER | R >= 2.0R, any regime | Close 50%, trail remainder 1.5xM15 ATR |
| REAPER | R <= -0.5R, TRENDING | Triple gate: SI<0.45 AND ER<0.25 for 2+ cycles |
| REAPER suppress | Asian hours | 00:00-07:00 UTC on XAUUSD/XAUUSD.x |

### Regime engine

in Session 4 (audit-cab-tf). H4 entries need H4 regime context.

## 9. Shared Infrastructure

### MT5 Gateway (mt5_gateway.py)
Single point of MT5 access. One threading.Lock. All bots use the same
gateway pattern — standalone fallback to raw mt5 if no gateway set.

```python
_GATEWAY = None
def set_gateway(gw): global _GATEWAY; _GATEWAY = gw
def _api(): return _GATEWAY if _GATEWAY is not None else mt5
```

IPC health: `_ipc_fail_count` increments on `symbol_info_tick()` None.
After 5 consecutive failures, `is_healthy` returns False, main thread
forces reconnect.

### SharedState (unified_runner.py)
In-memory store replacing CSV IPC. One RLock. Written by GhostWatcher,
read by GhostHunter. Also carries the circuit breaker flag.

```python
shared.conviction        # float 0-100
shared.adx               # float
shared.atr               # float
shared.regime            # RANGING / TRENDING_UP / TRENDING_DOWN / EXHAUSTION
shared.entries_allowed   # bool — circuit breaker gate
shared.daily_start_equity # sampled once at session start
```

### Circuit breaker
10% max daily loss. Blocks new entries across all bots. Watchers always
keep running — existing positions always managed regardless of the breaker.

### Live switches (config.json, no restart needed)
```json
"switches": {
    "supertrend_enabled": true,
    "cab_enabled": true,
    "ghost_grid": { "201": true, "202": true, "204": true }
}
```
Entries only — never management. Fail-open: if config.json is unreadable,
all switches default to enabled.

### MQL5 Failover (UnifiedFailover.mq5)
Single EA, all 9 magic numbers, one heartbeat file (cab_heartbeat.txt).
- Warn: 60s since last heartbeat
- Failover: 120s → 5xH1 ATR airbag trail on all positions
- Trail: only tightens, never widens existing SL
- ATR handles: cached per symbol (fixed Jul 2026 — was recreating handles
  every 5s cycle during the exact scenario where you want least failure surface)

## 14. Architectural Principles — Non-Negotiable

1. A switch or gate can never stop position management. Only entry
   creation is gatable. This is the root lesson of the CAB bug.

2. R-multiples measure outcomes. They must not mechanically trigger exits.
   Market state drives exit decisions.

3. Ghost Grid MAX_LEGS = 4 is non-negotiable during demo. Not 5, not 6.
   Evaluate statistically after 50+ grids, not impressionistically.

4. Sequential same-direction entries are directional confirmation, not
   compounding risk. This justifies per-instrument caps of 4.

5. Daily equity circuit breaker is the correct global safety mechanism.
   Per-instrument caps handle instrument exposure. Do not double-layer
   with a global position count cap.

6. Parameter changes go one at a time, measured against a clean baseline.
   The SL width change (0.2 to 0.35xATR) is the only parameter change in
   Week 2. Everything else waits for this measurement to be clean.

7. Demo execution is not live execution. The gap is largest for Ghost Grid
   (M1, execution-sensitive). More live micro-lot time needed for Ghost
   Grid specifically before scaling.

8. Never increase grid depth cap or widen grid stop during demo testing.
   Evaluate both statistically after 50+ grids.

9. **[PERMANENT] No arbitrary trade filtering.** The Knowledge Register
   and Order Router must never block trades based on unvalidated
   assumptions. Filters are only introduced after statistical analysis
   of raw logging data proves which market behaviors/regimes produce
   winners vs losers. Until that analysis is complete, every generated
   signal flows to the market unobstructed.
